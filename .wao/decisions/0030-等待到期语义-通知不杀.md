# 0030: 等待到期语义——通知不杀（Owner 方向裁定）

status: accepted（方向已裁；实施批待排期，代码行为在落地前不变）
date: 2026-09-18

## Context

TD-151/TD-154 摩擦史：`--wait-timeout` 到期会 abort 杀 worker（tkqfun 分秒实证），`--background` 不豁免（TD-148），`resume` 无 --wait 存在静默挂起/Job Object 连坐两张脸。P0 规程已落地（交付类一律 `--background` + 显式 `--cwd`）。

双席咨询（auditor run_202609171954584890yyaju / coder_mm run_2026091719550162535mtwt + 2026-09-18 批次裁定包）：auditor 判 detach/kill 为 ADR 级语义决策（高损失，不应顺手改）；coder_mm 建议与 TD-154 档位合并裁定（同属"等待窗 vs 执行死线"语义族）。

**Owner 裁定（2026-09-18 原话精神）**："等待时间到达之后只告知提醒 lead agent，语义决策应由 lead agent 根据当时情况做决定，WAO 不要轻易帮 lead agent 做强制决定。"并质询等待上限存在的目的——回答：上限的本职是**观察预算**（Lead 一次调用愿意花多少注意力等待），不是任务执行期限；历史实现把两者混同，是本债的根。

## Decision

1. **等待到期 = 通知，不杀。** 一切派发侧等待窗（`--wait-timeout` 及未来同族）到期只产生观察事实与 Lead 提示（`run_wait` 窗口到期 exit 0 的既有语义即此形），绝不触发 worker 终止。
2. **终止 worker 只有两个来源**：Lead 显式 stop；既有硬安全线（tokenBudget 闸门、workdir_escape 隔离守卫等——它们是安全语义，不是"等待"语义）。
3. **现行"到期杀进程"行为废弃**。过渡期：实施批落地前，P0 规程继续规避（交付类一律 `--background` + 显式 `--cwd`）。
4. **上限的定位 = 观察预算**，非执行死线。TD-154 的数值档位诉求随之降级——通知语义下上限高低无杀伤风险，维持现值、触发式观察即可。

## Consequences

- TD-151 根修实施批立项待排期：runManager 定时器路径改造（到期 → 观察事件+提示，去掉 abort 臂）+ 测试迁移 + `resume` 两张脸一并处理 + 行为变更条目（usage.md 场景 1）。
- TD-154 档位提案关闭（降级为触发式观察，见台账行）。
- 本 ADR 只定方向与语义；代码行为在实施批合入 main 前不变（到期杀仍存在，P0 规程有效）。
