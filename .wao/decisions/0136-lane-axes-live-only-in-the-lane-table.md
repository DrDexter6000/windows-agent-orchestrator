# 0136 车道四轴只有一个家：config/lanes.json

- 日期：2026-11-28
- 状态：accepted
- 来源：

  - 实现：第 158a 批（生效条目与全部读取面）；第 158b 批（模板与私有文件去掉四轴、`registry align` 退役写入、认证矩阵行 `modelId` 派生）。
- 关系：
  - 取代决定 0045 第 3 步 R3 裁定③在接线轴上的语义（runbook 与 0108 称它 G4：注册表赢、不一致即拒）。

  - 修订决定 0044 第 2 条（d′）、0081 第 1 条、0090 第 1 条里"模板也写四轴、与车道表逐条一致"的部分，第 158b 批起生效。

## 背景

- 四轴（backend、model.id、model.providerID、reasoning.effort）原本写在三处：私有 `config/agents.json`（实际生效）、`config/lanes.json`（入库，只做核对）、模板 `config/agents.example.json`。改一条车道的 effort 要三处一起改，不一致时 `--lane` 派发被拒；`registry align` 是给这套同步补的修法。
- 私有文件不入库，升级时 WAO 改不了它，却由它说了算。

## 决定

1. **四轴只从车道表取。** 所用注册表就是本安装的默认注册表（代码根 `config/default.json` 的 `registry` 键）时，派发、会审、续修、恢复、认证脚本和各读取面都读合并后的生效条目：同名车道的四轴取 `config/lanes.json`，私有文件只提供本机接线（cwd、binary、env、args 等）。私有文件里残留的四轴不生效，doctor 与 `lead_preflight` 报 INFO，可删。
2. **外来注册表自包含。** `--registry` 指向别的文件时不合并，条目自带的四轴就是生效值。
3. **读坏即拒。** 合并启用时，车道表缺失、不可读、结构或四轴不合法，一律以 `lanes_merge_unavailable` 拒绝，不回退私有文件里的旧值。
4. **一次请求一份表。** 每次请求只读一次车道表，选车道、预检、认证门与派发共用这一份。后台 runner 只认派发方显式传来的合并决定（关，或表的哈希）；没传或表已经变了，就在起跑前拒绝，诊断给出原因码。
5. **第 158b 批**：模板与私有文件不再写四轴；`registry align` 退役写入；认证矩阵行的 `modelId` 从车道表派生。

## 否决的备选

- **车道表改成指向私有文件的指针，或删掉车道表**：私有文件不入库，升级时无从更新；车道表还承载别名、暂停说明和认证键，删不掉。
- **保持三处同步，靠 `registry align` 修**：每次换型号或 effort 都要动三个文件，漏一处就拒派，等于给放错的家补工具。
- **只把 effort 搬进车道表**（方案会审两席提出的缩小版）：同样的问题在 backend 和 model.id 上原样留着。

## 已知边界

- 合入时已经在运行的 WAO 进程（多半是宿主会话里的 WAO MCP 服务）还是旧代码，它派出的运行会被新 runner 以 `lanes_merge_spec_missing` 拒绝；重启该宿主的 WAO MCP 服务即可。
- 第 158b 批之前，`registry align --apply` 仍会把四轴写回私有文件，写回的值不生效。
- 合并停用时 CLI 与 MCP 选车道用的表不同，是历史差异（TD-387）。
- 开发工作树用 `--registry <主检出>/config/agents.json` 时合并停用；私有文件去掉四轴后这种用法会缺 backend，第 158b 批一并处理。
