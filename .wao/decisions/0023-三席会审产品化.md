# 0023: 三席会审产品化
status: accepted
date: 2026-08-17

## Context
Owner 2026-08-17 五条需求：新消费者收到配两名副审建议；三席主审Lead加两外席最佳、两席次之；会审只在方案与交付物验收两阶段；强烈推荐但非强制显式理由后可跳过；强烈推荐跨族系会审。0019 的默认不审豁免无需留痕不新增守卫姿态与新裁定冲突，需显式 supersede 而非静默改写。本方案经方案阶段双席会审 coder_mm 加 auditor 修订为 v2 定稿含精确代码锚点。

## Decision
**supersedes 0019 的以下条款**（其余保留，见下）：
- 0019 §2 "默认不审" → 改为"三席会审是推荐标准"（强烈推荐但非强制）；
- 0019 §4 "豁免无需留痕证明" → 跳过需 `--panel-skip-reason` 显式登记闭集理由码；
- 0019 Non-goals "不为本惯例新增守卫" → 本决策新增纯展示层（onboarding 分级块、
  doctor `panel_readiness` INFO、`wao stage` panel 字段），仍不做门禁、不自动派发副审。

**保留并引用的 0019 条款**：§3 席位回避（身份回避优先于家族表；任一席的评审者
不得是被审产出的作者或共同作者；规避不可满足时 Lead 裁量缩小或破例并注明）、
§5/§56 红线（评审意见是证据不是验收；`run_delivery_decide` 只由 Lead 调用；
无 auto-accept 路径）、两席分配语义（实现者视角席 coder 系取一 + 对抗视角席
auditor 默认 / coder_mm 轮换替补）。

**Owner 五条需求契约（2026-08-17，不可动摇）**：
1. 新消费者（Lead Agent 与人类用户）收到"配两名副审"建议；
2. 三席会审（主审 Lead + 两外席）最佳，配不齐则主审 + 一副审两席为次之推荐；
3. 会审只发生在方案阶段与交付物验收阶段；
4. 强烈推荐但非强制，显式理由（condition）后可跳过；
5. 强烈推荐跨族系大模型会审。

**三席/两席分级定义**（单一实现 `src/application/panelReadiness.js`；
onboarding 模板面与 doctor 已配置面各包一层输入调用，禁止两处各算；R9-C 返工后
按**席位候选**计数——对抗席候选 = auditor 专职 + coder_mm 替补、实现席候选 =
coder 系通道，researcher/tester 等非席位角色不进席位计数与建议）：
- 三席可用（推荐标准）：≥2 名可用席位候选（readyState=ready）→ 建议席位组合
  （对抗席优先 + 实现席，避同族优先，含推断族系标签）；≥2 席位候选但 0 对抗席时
  仍判三席（物理可配），必附一行"无对抗席候选（auditor/coder_mm）——两席分配
  语义要求对抗视角，建议补配"提示，doctor 该形态不静默；
- 两席可用（次之推荐）：恰 1 名可用席位候选 → "补齐第二个副审（建议不同族系）可升级三席"；
- 无可用席位候选：跳过提示（`--panel-skip-reason` 登记）。
- `login_based`/`unknown` 不计入"可用"但如实展示（auditor 即
  login_based——文案不得把登录态当已验证讲；serve 注入型 backend 单列"注入式
  认证（serve 探测不覆盖）"，探测未知展示"探测未知"）；未知族系 ≠ 同族（不参与
  多样性判定）；单 worker（唯一 worker 即被审产出作者，0019 §3 回避）时两席建议
  事实空转，文案明说。

**两阶段限定**：panel 字段只在 stage 2（方案）/ stage 4（交付物验收）登记；
其余 stage（1/3/5/6）带 panel 参数 fail-fast，文案固定为"panel 字段只在方案（2）
/交付物验收（4）登记"（不得写成"会审仅发生在两节点"——避免被读成禁止多轮）。
同一 stage 允许多条 panel 记录（返工/窄复核的真实形状），不设唯一性校验。

**跳过闭集码（SSOT：`src/waoStage.js` `PANEL_SKIP_REASONS`，四码）**：
`no_reviewer_available` / `low_risk_small_task` / `time_critical` / `owner_direct`。
非法码 fail-fast；细节差异（如 provider 临时不可用）进既有 `--note`，不扩闭集。

**跨族系推荐**：族系经 `src/application/modelFamily.js` 推断（模型 id 归一剥
`[1m]` 类后缀取首段；无 model 块按 backend 名兜底；未识别 → 未知族系）。该表
不是契约、展示专用，消费者不得据此门控；dispatch/delivery 不得 import。可用
副审的已知族系单一时给一行"跨族系是更强推荐"提示。

**落地面（全部纯展示输出：stdout JSON 加性字段或既有命令族内新增 INFO）**：
- `wao stage 2/4 --panel-seats <id[,id]>`（自报、未验证；registry 存在性校验；
  评审旁证走既有 `--artifacts` 的 runs/<runId>.jsonl 路径）与
  `--panel-skip-reason <code>`；两者互斥 fail-fast；
- stage 2/4 落盘成功且无任何 panel 字段 → 输出 JSON 加性字段 `panelAdvisory`
  （未记录会审提示；exit 0 不变——非门禁）；
- stage 4 成功输出固定复述红线："评审意见是证据不是验收；run_delivery_decide
  只由 Lead 调用"；
- 裸 `wao stage` 输出 panel 分布 + skip 理由分布（仿 declare byReason）；
- `wao onboarding` 两出口（needs-selection / selected--apply）打印分级块
  （模板面：入库模板 + 环境探测；onboarding 不读用户 registry）；
- `wao doctor` 条件 INFO `panel_readiness`（已配置面：registry + 既有探测；
  仅可用副审 ≤1 时打印，三席齐备静默；registry 缺位沿 U1 INFO 跳过模式；
  INFO 不计 DEGRADED）。
- STAGE 索引行扩展 panel 摘要列；无 panel 字段的旧行照常解析（向后兼容）。

**定位红线（不变）**：Advisory 产品化，非门禁——派发/验收/交付既有门零改动；
`run_dispatch`/MCP 22 工具面字节不动；不自动派发副审；不新增持久子系统（复用
stage 的 pipeline/map.md 索引）；不强制族系。


## Consequences

- **落地面清单**（全部纯展示输出，无门禁、无自动派发）：`src/application/panelReadiness.js`
  （分级单一实现：席位角色分类 + 六态映射 + 建议组合）、`src/application/modelFamily.js`
  （族系推断，展示专用非契约）、`src/application/onboarding.js` +
  `src/commands/onboarding.js`（模板面分级块与 `panelReadiness` 加性 JSON 字段）、
  `src/commands/doctor.js`（已配置面 `panel_readiness` 条件 INFO）、`src/waoStage.js` +
  `src/commands/wao.js`（stage 2/4 panel 字段、STAGE 正文红线句与 `pipeline/map.md`
  第 5 列留痕）。
- **advisory 性质**：所有输出不改变任何派发/验收/交付门；INFO/提示不计 DEGRADED、
  不改退出码；panel 字段缺席照常落盘（exit 0）；不自动派发副审、不新增持久子系统
  （复用 pipeline/map.md 索引）。
- **对消费者的行为变化**：新消费者（Lead Agent / 人类用户）在 onboarding 与 doctor
  收到"配两名副审（对抗席 + 实现席）"建议；分级只统计席位候选（auditor/coder_mm
  对抗席、coder 系实现席——0019 两席分配语义保留），researcher/tester 等非席位角色
  不进计数与建议；≥2 席位候选但 0 对抗席时仍提示补配（doctor 不静默）；跳过会审需
  `--panel-skip-reason` 登记闭集理由码；建议组合/在场候选的族系标注均带"推断"字样。
- **0019 supersede 影响**：0019 §2/§4/Non-goals 被取代（默认不审 → 推荐标准；豁免
  无需留痕 → 显式登记；不新增守卫 → 纯展示层）；§3 席位回避（含 sessionReuse 独立性
  侵蚀注记）、§5/§56 红线与两席分配语义保留引用；0019 头部已加 superseded-by 反向
  指针（导航事实，历史决策正文不改写）。
