## Context

Owner 2026-10-10 提案：四角色（coder/auditor/researcher/tester）全部允许并鼓励会话复用，理由=①复用上下文提高理解连续性；②复用 KV-cache 降低成本。咨询+核实发现：

1. **字面改动是无效操作**。复用真门在 `src/application/runDispatch.js` reuseEligible（洞②：显式 lane/role 派发永不进复用路由）；裸 agentId 派发只读席位字段；8 车道别名表已全空——`config/roles.json` 的 researcher 条目在现行派发面走不到。当前唯一活的复用=裸派 glm-flash 命中席位字段，且 roleSha256 恒 "none"（席位无 systemPrompt，键材料取错了来源）。
2. **三个 P0 缺陷**（开门前必须修）：
   - 失败即弃缺失：resume 判定只看"prior 终态 + session.created 可寻址"，不问终态成败——失败会话（幻觉/死循环）会被原样接着用，且确定性派生的 uuid 使"丢弃会话"机制上做不到（claude-code 的 --session-id 直接用该 uuid，first 轮会接上坏会话）。
   - 角色指纹取自席位 systemPrompt（恒 "none"）而非本次派发的角色——开门后同车道不同角色帽会共用 provider 会话。
   - 无显式逃生口：Lead 无法强制某次派发开新会话。
3. **角色×通道差异**（两席共识）：auditor 的验收价值=独立性，复用带来自我确认偏差（Owner 理由①对 auditor 验收恰是负收益）；zcode 通道 resume 有已声明残余 B′（历史头部插入 parts → 旧 stop 序号右移 → 可能提前误报完成），证据角色（tester PASS/FAIL、coder 交付判定）经不起；kimi-web 无会话级 abort 杠杆；KV-cache 降本只在 kimi-web/zcode 可计量，claude-code/codex 是未计量假设；全会话复用使同身份并行派单撞 ReuseBusyError（Contract 6 串行化）。

## Decision

1. **洞②修订**：显式派发（lane 与/或 role）**可**进复用路由，条件不变式收紧为 `effectiveReuse === "lead_workspace" && !publicDelivery`——显式 role 派发的生效政策读 `roles.json[role]`（终局权威语义由此成为真实开关，不再是装饰）；显式 lane-only 派发对齐裸派语义（席位字段兼容来源）。delivery 派发永远 fresh（不变）。
2. **P0 护栏（开门前置，本批全落地）**：
   - **失败即弃 + epoch**：prior 终态非 `completed`（failed/aborted/timed_out）→ 不 resume，槽位覆写为 first，且 uuid 代数 +1（epoch 进派生材料；epoch=0 与旧派生逐字节相同——存量 researcher 会话零迁移）；stale-crash 收回槽位同样 +1（状态不可知的会话按可能已中毒处理）。prior 终态=completed 才允许 resume。
   - **角色指纹改取本次派发的角色正文**：roleSha256 = sha256(实际注入的角色合同正文)（显式 role 派发）；裸/lane-only 派发保持 "none" 键（与 hatted 键天然隔离，cross-hat 不共用会话）。
   - **fresh 逃生口**：per-dispatch `fresh` 参数（MCP run_dispatch；CLI 派发本就是一次性 leadSession=永远 fresh，不加死旗标）——强制 first + 槽位覆写 + epoch+1（=换新 provider 会话），由 Lead 裁量使用（不变式 4/6：复用决策保持确定性、归 Lead）。
3. **分级启用（staged）**：
   - researcher：维持（唯一已验证档；显式 --role researcher 派发自本批起可复用）。
   - tester / coder：**暂不入表**——待 zcode B′ 残余关闭或按车道排除机制落地后另批启用（本批只开门+护栏，不扩表；防止 tester 的 PASS/FAIL 证据经不起 B′）。
   - auditor：**不入表**。验收模式复用=腐蚀独立性（岗位职责本身）；advisory 模式复用列为未来选项（需先有模式分裂机制，另立项）。
4. **在册知悉**：kimi-web 失控复用会话无 WAO 内停止杠杆（等超时/人工处置服务器侧）；同身份并行派单会被 busy 拒（Lead playbook 须按串行规划）；claude-code/codex 的 KV-cache 经济性未计量（理由②按假设对待，kimi-web/zcode 可核账）。

## Consequences

- `docs/02-architecture.md` §4.10（Expert Session Reuse）行为合同同步（失败即弃/epoch/fresh/开门条件）。
- MCP 面 run_dispatch 增 `fresh` 参数 → wire 重冻 + `npm run gen:surface` 再生成提交。
- 复用身份键材料升维（+epoch）只增不减（0045 §1.6 纪律延续）；路由条目形状增可选 `epoch` 字段（缺席=0，旧条目零迁移）。
- 转录审计事件 {mode, turn} 不变；epoch 不进转录（它只活在派生材料里，取证经 priorRunId 链回溯照旧）。
- 触发本修订的原始提案（四角色全开）按本档分级执行；Owner 若日后裁定 auditor 全模式复用，须再立修订档。
