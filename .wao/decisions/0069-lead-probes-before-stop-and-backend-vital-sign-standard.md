## 决定

1. **下钻给出命令原文，缺省最新在前。**
   - `run_activity` 的 command 条目新增 `text`（命令原文）与 `truncated`。与 message 文本走同一条路径：脱敏 → 清控制字符 → 截断。上限 400 字符、保留开头——命令是什么看的是开头；一条带管道和重定向的 shell 命令在 400 字符内放得下，内联脚本只留头部。
   - MCP `run_activity` 的条目缺省最新在前（新增入参 `order`，`asc` 按时间顺读；cursor 往更早翻）。此前从最早的 8 条给起，Lead 要翻到底才看得到"现在在做什么"。
   - 脱敏两层，先后有序：先把环境里按名字识别出的密钥值整段替换（既有），再过一层形状兜底（`redactSecretShapes`，只用在命令原文上）——名字像密钥的赋值（`XXX_API_KEY=…`、`"api_key": "…"`、`$env:PRIVATE_KEY="…"`，带引号的值连同转义引号整段替换）、命令行参数（`--api-key 值`）、`Authorization` 头与 `Bearer …`（大小写不敏感）、URL 与 `curl -u` 里的口令、PEM 私钥块，以及 AWS / `sk-…` / GitHub / Slack / Google / npm 令牌与 JWT 的形状。顺序不能反：形状先行会把环境值切碎，整段匹配随之失效。此前"命令里写死的密钥不会到 Lead 面前"由"根本不给命令"保证，放开之后由这层兜底承接其中有形状的那部分。
   - 如实边界：没有形状的秘密不在覆盖范围内（`mysql -p<口令>`、短于 8 字符的值、自定义格式的令牌）；会误伤名字里带 TOKEN / SECRET 的普通配置（`TOKEN_COUNT=12345678` 会被遮掉）——宁可少看一段，不漏密钥；命令里出现的绝对路径照原样给出（`file_written` 的路径字段仍不给绝对路径）。tool_use 仍只给工具名，tool 的输入输出仍不给。
2. **中止前先探明、并说明理由——两个 Lead 面都是必填。**
   - MCP `run_stop({ runId, observedSeq, reason })`；CLI `stop <runId> --observed-seq <n> --reason "<理由>"`。`observedSeq` 是 Lead 做决定时看到的转录位置：`run_activity` 最新一条的 `seq`（没有条目填 0），或 CLI `status` 输出的 `observedSeq`。
   - 服务层（`src/application/runStop.js`）在任何终态认领、事件追加、击杀之前校验：理由 6–400 字符；`observedSeq` 必须是该运行转录里真实存在的一条（或 0）；在它之后运行被重放过（`run.rerun`——停止目标换成了 Lead 没看过的进程）即拒，不论过去多久；在它之后落下的 worker 事件若已超过 2 分钟，判为"照着过时的状态做的决定"。任一不满足即拒绝，零事件、零副作用。刚落下的事件不算过时——否则话多的 worker 永远停不掉；时间戳在未来（时钟回拨）按刚落下处理。
   - 通过后，理由、观察位置、其后新增的 worker 事件数、最近一次生命体征距今多久，一并记进 `run.stop_requested`（取自认领之前读到的快照；并发增长时不保证覆盖到落盘那一刻）。
   - 不带这两项的服务层调用只剩内部 / 机制测试路径。
3. **"有生命体征的 10 分钟内不要随意中止"是建议，不是闸。** 生命体征 = 任何一条 worker 事件（动作、正文、思考、`runtime_activity`）。写进 `run_stop` 的工具描述；转录静默 ≥30 分钟的 advisory（CLI 与 MCP）在最近 10 分钟内有体征时多一句。stop 不因此被拒；体征距今多久记进转录，事后可查。
4. **生命体征与收口方式是每个后端适配的标准登记项。** 口径在 WAO 抽象层只有一条——没有生命体征才由控制面收口，有生命体征去留归 Lead；适配层逐个落地。
   - `src/backends/factory.js` 的 `CAPABILITY_NOTES.<backend>.vitalSigns` 对每个后端必填：读得到哪些体征、哪些落成转录事实、有哪些"等不到进展"的收口门以及它们与体征的关系、哪里是例外。生成器缺项即红；内容渲染进 `docs/surface/certification.md`。八个现有后端已登记。
   - `docs/certification-runbook.md` 的新后端入册流程加一条：①列出读得到的体征；②每道收口门到点先看体征，全无才收口；③让收口门续命的体征落成 `runtime_activity` 事实；④做不到的地方如实登记为例外。
   - 按第③条补齐 kimi-web：凭 serve 证词续命时落 `runtime_activity`（status `serve_active`，闭集扩一员）。此前这类续命在转录里不留痕。

## 如实边界

- **"必须先 run_activity"校验的是位置，不是调用记录。** `run_activity` 是零写入的只读工具，控制面不知道它有没有被调用过；校验的是 Lead 给出的位置够不够新。一个从别处（比如 `run_wait` 的 `cursor`）拿到最新位置的 Lead 也能通过；一个刚派发不到 2 分钟的运行，位置填 0 也能通过。它挡住的是"照着过时的状态去停"和"重放之后照着旧进程的状态去停"，挡不住"拿到了位置却没读内容"。会审 sol 据此把这项落法判为不成立（UNSOUND），kimi 判为成立（SOUND）；Lead 的判断是它如实做到了能做到的那一半，标题不该写成"证明看过"。
- **理由只校验长度，不校验内容。** 控制面不判断理由成不成立。
- **进程式后端（codex / claude-code / kimi-code）与 deepseek 在长工具调用期间仍不落任何体征事实。** 这些后端没有收口门，所以不会被控制面误杀；但 Lead 在下钻里只看得到"一条命令在跑、还没回来"，看不到"进程在干活"。"10 分钟内有体征"这条建议在这些车道上因此保护不到长命令——命令原文是 Lead 在那里唯一的线索。给进程式后端加只供观察的进程活动事实，未做。
- **这是一次对宿主可见的不兼容变更**：只带 `runId` 的旧 `run_stop` 调用、不带两个 flag 的旧 `stop` 脚本都会被拒；宿主缓存的工具 schema 需要刷新。
- **命令摘要只留开头 400 字符**：关键动作在尾部的长内联脚本看不全；tool_use 的输入、最近一条工具输出的尾部仍不给。Owner 的"从最新/最近吐出的动作/信息"本批只落成"条目最新在前"，是否还要这两样留给 Owner。
- **owner dashboard** 的接口载荷因共用同一投影而带上了命令原文，页面本身没有改、仍只渲染退出状态。
- **MCP 工具清单体积**：85221 → 85915 字节，距 Owner 硬顶 85939 还剩 24 字节；冻结上限与描述字节上限按实测重冻（见测试文件注记）。下一次再给 MCP 加字段，要么 Owner 抬硬顶，要么先在别处瘦身。
- 观察位置的 2 分钟、理由的 6 字符、命令的 400 字符都是凭经验取的值，没有统计依据。
