# 0049 安装权威收敛：认 A 为唯一物理安装（junction 暴露）

- 编号：0049
- 日期：2026-10-09
- 状态：accepted（Owner 2026-10-09 批准；kimi+opus 双席预审 consult_20261009081329035swaqvc 全票推荐 (a)）
- 取代：2026-10-02 安装形态三分工裁定（AGENT_ONBOARDING §2"B/C 分工"段，原段落标注取代指针）

## 背景（事实，2026-10-09 Lead 亲手实证）

- 本机物理安装只有一份：开发仓 A=`D:\projects\windows-agent-orchestrator-poc`。
- `~/.agents/skills/wao-orchestrator`（技能发现路径）与 npm 全局包均为**指向 A 的 Junction**（`dir /AL` 双实证）——同体视图，非拷贝，文件系统级零漂移。
- 10-02 裁定指定的 C=installer 日常执行根（如 `%USERPROFILE%\wao`）**从未安装**（目录不存在）；全局 `wao` 入口事实上 → npm junction → A。
- 10-02 裁定撰写时预设 B 为"会漂移的整仓拷贝"——现实是 junction，同步义务这个最大运营成本不存在。

## 决定

1. **A 为唯一物理安装与执行权威**；技能发现与全局 `wao` 入口经 junction 直达 A。
2. 10-02 裁定中"B 拷贝=技能发现专用 / C=日常执行根"的分工**废止**（B 被证为 junction、C 从未存在）。
3. **C 方案挂起不删除**，重启触发条件（满足其一才议）：需要向非开发机分发；或需要冻结稳定版与开发版并行。installer 形态继续面向无开发仓的外部机器（README 默认不变）。
4. **main 常绿是稳定性契约**：A 兼任开发仓与执行权威后，main 的脏状态即全局 `wao` 的行为——npm test 全绿才合入的既有纪律是本决定的安全底座。
5. **doctor advisory（非阻断）**：junction 目标=当前检出时，报告检出分支与未提交改动数（决定落地同批实现）。
6. **安全红线**：删除任一 junction 必须用 `rmdir`（非递归）；`Remove-Item -Recurse` 会穿透链接删除主仓本体。
7. **第三方风险在册**：任何对 `~/.agents/skills` 做递归操作的第三方工具（技能管理器/备份/清理脚本）会作用到开发仓本体——本红线只约束 WAO 自身操作，第三方行为靠使用者知悉。

## 通用文档语义（AGENT_ONBOARDING 通用段改写依据）

执行权威=唯一一份物理检出；技能发现路径与全局入口以目录链接（junction）指向它，链接同体、无同步义务；任一入口若是物理拷贝而非链接，它就是漂移源（doctor 如实报告），收敛方式=改为链接或删除，**不维护拷贝同步**；installer 根是无开发仓机器的安装形态，不与开发仓同机并存。

## 后果

- TD-191⑥ 机器半关账（事实=已收敛；doctor junction 探测+分支/脏态 advisory 同批落地）。
- 开发/执行隔离以"main 常绿 + doctor advisory 可见性"替代"第二份安装"（隔离从未生效过——C 不存在；为它付永久同步税无消费者）。
- 未来若触发条件命中，按新决定记录另立（本决定只追加不回改）。
