# 0122 保持唤醒期间按用户的屏保设置代为启动屏保

- 日期：2026-11-10
- 状态：accepted
- 来源：
  - 宿主项目反馈 `fb_20261110T082418Z_cm3vq1`：WAO 运行期间 Owner 设的灭屏与屏保全部失效，屏幕长时间停在同一画面，有烧屏风险。
  - Lead 摆了两个方案：方案 1 插电时不申请显示需要；方案 2 照旧申请，同时代为启动屏保。Owner 2026-11-10 答"同意方案2"。
  - 第 97 批。
- 关系：修订决定 0093。申请照旧是"系统与显示都需要"，三处持有与关闭开关不变；本决定只改持有子进程在持有期间做什么。

## 背景

2026-11-10 统计 System 日志里 2026-08-21..11-10 的 Kernel-Power 566 事件（`Get-WinEvent` 只读查询，按字段 `PreviousSessionType`、`NextSessionType`、`Reason`、`PowerStateAc` 分组计数）。每条 566 记录一次会话切换，会话类型 0 亮屏、1 灭屏、2 睡眠。

1. 灭屏不等于睡眠：插电时亮屏因空闲（`Reason=12`）转灭屏 1,957 次，灭屏后因空闲转睡眠 0 次。Windows 称 506 为"进入新型待机"，但它在这台机器上与每一次灭屏一一对应：506 共 2,756 条，正好等于"下一会话为灭屏"的 566 条数。所以单看 506 判断不了机器是否睡着。0093 背景里"用电池时屏幕空闲约 3–5 分钟就进新型待机"，也是把灭屏当成了入睡：用电池时灭屏后因空闲入睡 26 次，宿主项目 carloha_fde 的归因是都撞上了当时的电池"N 小时后睡眠"定时（现已设为"从不"，`ES_SYSTEM_REQUIRED` 本来也挡得住），Lead 没有复核这一归因。
2. 除此之外，真正入睡的路径有两条：用电池时合盖（约 5 秒），以及屏幕已熄灭时交直流切换（566 的 `Reason=28`，插电侧 52 次、电池侧 45 次；拉各斯常停电）。持有显示需要时屏幕不熄灭，这两条都没有发生（0093 记录的 10-29 合盖实测；11-10 用电池合盖、WAO 持有中，8 分多钟无待机）。
3. 显示需要的申请在这台机器上同时挡住灭屏和屏保。微软文档说它不挡屏保，与实际不符。WAO 运行很频繁，所以 Owner 的 10 分钟灭屏、5 分钟屏保在运行期间几乎都不生效。
4. 持有显示需要时，用 `Start-Process <SCRNSAVE.EXE> -ArgumentList '/s'` 启动用户的屏保：它能起来，窗口可见、占满屏幕、成为前台。这样启动时，`SPI_GETSCREENSAVERRUNNING` 一直是假。
5. carloha_fde 的常驻保持进程 11-10 用同样做法跑了一上午：空闲 701 秒时起屏保，一直盖到 Owner 回来。

## 决定

1. 申请照旧：`ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED`。它是这台机器上唯一实测挡住两条入睡路径的办法。
2. 持有子进程不再只等父进程退出，改为每 15 秒看一次。以下条件都满足时，按用户自己的设置启动屏保：
   - 子进程在交互会话里；
   - 用户开着屏保；
   - 屏保文件存在（路径里的环境变量先展开）；
   - 键鼠空闲时间达到用户设的屏保时长；
   - 当前没有屏保在跑。
   设置每一轮重读。先判便宜的条件，最后才扫进程表：扫一次约 0.2–0.4 秒（11-10 实测），用户在用电脑时每轮几乎没有开销。循环体里任何一步失败只跳过这一轮，不影响保持。
3. "没有屏保在跑"要求三者都不成立：本进程上次起的屏保还没退出；本机有可执行文件以 `.scr` 结尾的进程（扫的是全机进程表，不分会话）；系统报告屏保在运行。最后一条对代起的屏保不起作用（见背景 4），起作用的是前两条。
4. 父进程退出时，持有用的 PowerShell 子进程随之退出、持有结束；它起的屏保不结束，遇到键鼠输入照常退出。`WAO_KEEP_AWAKE=0` 仍关闭整件事。

## 否决的备选

- **插电时只申请"系统需要"、用电池时再加显示（方案 1）**：屏幕熄灭时一停电，机器几秒内就会睡过去（原因码 28 共 97 次）。检测到停电再补申请来不来得及，没测过。屏幕已熄灭时补申请能不能挡住入睡，也没测过。
- **改电源或屏保设置**：那是 Owner 的系统设置。
- **用户没开屏保时也代为黑屏**：不替用户做没设的事。

## 已知边界

- 插电时"N 分钟后关闭显示器"在持有期间仍不生效：屏幕是黑的，但面板没有断电。
- 屏保最晚在达到时长后约 15 秒起来。几条运行同时持有时，各自的子进程可能在同一轮各起一个屏保，遇到输入都会退出。
- 用户没开屏保、没设屏保文件，或时长为 0 时，持有期间屏幕照旧常亮。
- 锁屏时输入桌面是登录界面，代起的屏保落在看不见的桌面上；持有期间锁屏画面照旧常亮（0093 起就是这样）。
- 用户设了"恢复时显示登录屏幕"时，代起的屏保退出后很可能不锁屏（这台机器上没设，未实测）。
- 非交互会话（例如会话 0 的计划任务）不代起屏保：那里读到的是服务账户的设置，又没有输入，可能起一个看不见、也没人关的屏保。
- WAO runner 起的子进程在 libuv 作业里（关作业即杀、允许静默脱离），持有子进程起的屏保会静默脱离这个作业，runner 退出后照样留着（会审用替身进程实测）。
- 端到端冒烟（11-10，替身父进程、阈值 1 秒、每秒一轮）：持有期间执行状态为 0x3；空闲达到阈值后代起了屏保；父进程退出后，持有子进程随之退出。
