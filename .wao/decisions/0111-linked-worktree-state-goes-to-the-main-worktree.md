# 0111 链接工作树的 .wao 本地状态落到主工作树

- 日期：2026-11-04
- 状态：accepted
- 来源：本仓 10-31 至 11-04 提交说明引用的 80 场会审，67 份组记录随开发工作树一起被删；Owner 2026-11-04："其它WAO用户（其它Agent）如果也误删了怎么办？还得从WAO作为工具本身来想办法"。方案会审 consult_202611041005392875e9duy（sol、deepseek-flash FIX_FIRST）与复核 consult_20261104101446328qvtatv（sol FIX_FIRST），均已吸收。
- 关系：把 0099 的"链接工作树算同一个项目"用到 `.wao/` 本地状态。

## 决定

1. `.wao/` 里除 `decisions/` 外的本地状态（会审组记录、pipeline、handoff、project.md、migration），在链接工作树里读写主工作树的 `.wao/`。找主工作树用 0099 的 R4 与 R8，只看工作树根，读不出照旧（R4 已回溯到仓根的，按仓根）。
2. `decisions/` 随分支提交，留在工作树。
3. 命令行显式给的 `--state-dir` 照旧按 cwd 解析；配置里的 `stateDir` 只给名字。
4. 按 id 读会审组记录时，主工作树里没有就读改动前位置的那份（只限文件不存在）；doctor 提示工作树里留下的其余本地状态。

## 否决的备选

- 删树时自动拷出：`git worktree remove` 不经过 WAO。
- 只在 doctor 里提示：要有人看，跟写进记忆一样靠人记得。
- 整个 `.wao/` 落主工作树：决定档进不了分支的提交。

## 已知边界

- 以 `runDir` 父目录为根的记录（serve 维护台账、lineage 锁、迁移台账）跟着运行存储走。进程 cwd 在链接工作树里、又没给 `--run-dir` 时，运行存储本身在树里，转录也会随树删掉：在链接工作树里用 WAO，从主检出启动或给 `--run-dir`。
- 几棵工作树同时写同一份 `pipeline/map.md`、`handoff/map.md`，与主检出上两个会话并发写同类，不另加锁。
- 首次在链接工作树里 `wao init` 时，`.gitignore` 规则写在工作树、随分支合入；合入前主检出不忽略这些槽位。
