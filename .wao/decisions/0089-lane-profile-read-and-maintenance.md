# 0089 车道画像的读与维护：lead_preflight 一次看全，巡检时复核，纯画像数据改动不跑全量

- 日期：2026-10-18
- 状态：accepted
- 来源：Owner 2026-10-17 问 Lead 读到的车道信息走什么流程、是否优雅、Lead 怎么提修订意见。Lead 在答复里提出本决定的做法，Owner 2026-10-18 回复"批准同意继续推进工作"。
- 关系：修订 0087 §4（投影的字段）；落实 0087 §6（写规则）与 §8（版本巡检）的做法；修订 0077（纯画像数据批次不跑全量）。
- 合入授权：Owner 2026-10-12——"只要是你联合会审过的，我都许可 commit & push"。

## 背景

1. 一条车道的信息分在三处。画像在 `lead_preflight.lanes`，暂停说明只在 `registry_list`，上下文窗口、能否看图与证据只在命令行 `wao lanes`。只走 MCP 的 Lead 拼不全。
2. 画像一节约 8 KB，其中 33 个未评格（`{stars:null,…}`）占 1.6 KB。
3. SKILL.md 的派发前检查没提画像。
4. 画像没有固定的复核节奏。会审统计靠一次性脚本，每次改画像数据都要两席会审加一次约 11 分钟的全量，一批要一个多小时。
5. 重算会审统计时发现，会审的答复解析认不出行首加粗的结论行（`**Q1：FIX_FIRST**`）。10-06 到 10-17 的会审里有 35 席因此没被认出，"两席结论不一致"的提示也跟着漏报。

## 决定

1. **lead_preflight 一次看全。**
   - `lanes` 每行加三个字段：`dispatchHold`（车道表的暂停说明，与 `registry_list` 用同一校验）、`contextWindowTokens`、`imageInput`。
   - 未评的维度不投影；`scale` 行末写"未列出的维度＝未评"。
   - `registry_list` 仍是凭据与认证明细的读取面。
2. **一项事实一处。** glm-pro 的注意事项"不能看图"与 `imageInput` 重复，删去。
3. **Lead 的操作手册写明用法。** SKILL.md 的派发前检查改为：从 `lead_preflight` 的 `lanes` 选车道，星级是参考不是路由；对画像有意见用 `wao feedback submit` 提。
4. **画像复核挂在 30 天巡检上。** 巡检收口加一项：
   - 用 `npm run lane-review-stats` 重算会审席位统计；
   - 查这期间各车道的失败诊断有没有新规律；
   - 复测待复核的车道；
   - 按 0087 §6 改画像，并汇报 Owner。

   统计脚本读会审记录与席位转录，结论用会审自己的解析器取，与 `wao consult show` 同源。
5. **会审锚点认行首加粗。** 裸编号锚点允许行首带 `**`（"**Q1：…**"、"**Q1**：…"）。句中加粗、列表前缀、没有冒号的加粗仍不算锚点；`__` 也不认：真实答复里没出现过，而且下划线是单词字符，包在结论外会挡住取值。按新规则，10-06 到 10-17 的会审多认出 25 席（120→145）。
6. **纯画像数据批次走轻流程。** 只改 `config/lane-traits.json` 的批次：
   - 跑画像校验测试（laneTraits、laneProfile）加横切守卫组；
   - 一席会审；
   - 不跑全量。

   理由：画像只进只读视图，坏数据只会让那一行被省略并留一条观察；派发、门禁、认证都不读它（0087 §5 的守卫测试钉住）。

## 否决的备选

- **把画像也放进 `registry_list`。** 两处都有画像，就是两份投影要维护；`registry_list` 管库存与凭据。
- **未评格仍投影成 null。** 七项标签已在 `dimensionLabels` 里，缺席即未评，null 格只是噪音。
- **统计脚本自带宽松的正则。** 会与会审自己的解析不一致。该修的是解析器。
- **由 WAO 自动改画像。** 星级是判断，归 Lead（不变量 4）。
- **纯画像数据批次照跑全量。** 一批一个多小时，重复验证的只是与代码无关的数据；数据形状已有专门测试。

## 已知边界

- 只有画像文件里有条目的车道才有行。没有画像的车道，暂停说明仍只在 `registry_list` 与 `wao lanes`。
- kimi 席位的最终答复有时把过程叙述和结论粘在同一行，锚点认不出：10-06 到 10-17 的 59 席里有 4 次，见 TD-313。
- 统计按席位的 agentId 计。同一车道改过名字的历史记录（如 opus 与 claude-opus）分开计。
