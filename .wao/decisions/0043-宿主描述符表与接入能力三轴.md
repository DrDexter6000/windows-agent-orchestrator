# 0043 宿主描述符表与接入能力三轴（TD-191①② 执行契约）

## Context

TD-191①：`mcp bind` 仅支持 codex（SUPPORTED_HOSTS 手写单值），第三方宿主接入无单源；`onboarding.js buildHostExamples` 已硬编码第二份宿主清单（漂移中）。两席会审一致裁定走"收窄案 A"。

## Decision

1. **宿主闭集唯一权威 = `src/hostAdapters/hostDescriptors.js` 冻结描述符表**。每宿主三能力布尔（正交，会审裁定"模板可出/可自动绑定/真机验证是三种能力"）：`snippet`（可产出该宿主形态注册片段）、`autoBind`（mcp bind 真写其配置）、`hostVerified`（已在真实宿主验证加载）。
2. `SUPPORTED_HOSTS` 从表派生（导出名与消费点不变）；未知宿主 fail-closed 报 known hosts。
3. `mcp bind` 对 snippet-only 宿主（autoBind=false）**emit 精确片段而非拒绝**，零写入；输出必须明说 "SNIPPET GENERATED — NOT BOUND"（输出片段 ≠ 绑定成功，会审裁定）。`status`/`unbind` 对 snippet-only 宿主返回显式 `not_applicable` / `nothing_to_unbind`。
4. `buildHostExamples` 改从描述符表派生——**消灭第二份宿主清单**（会审验收判据）。
5. 表纪律：仅纳入格式已核实的宿主；新宿主入场须携带 hostVerified 证据（真机加载）或显式 false + 验证路径。zcode 入表路径 = dry-run（schema 校验 + scratch stdio spawn）+ Owner 在场真机步骤（备份→追加单键→重启→观察→还原）；dry-run 通过仅支撑 hostVerified=false 的入场，不得声称"实测接入"。
6. MCP 工具面零触碰（bind 是纯 CLI/Human Owner 面）——无 wire refreeze。

## Consequences

- 第三方宿主从"拒绝"变"恒有用"（emit 片段）；claude-code 立即受益。
- onboarding `--host`（②）消费同一张表，宿主接入文档只剩一处事实源。
- autoBind 闭集当前 = {codex}；新增须先在 hostAdapters 层落地该宿主适配器（真写配置 + rollback 纪律同 codexMcpConfig）。
- "实测/verified" 声称边界由 hostVerified 轴承载——dry-run 不计入。
