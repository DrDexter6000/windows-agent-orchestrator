# 0032: 两层验证与认证（组件层 + 组合层）

status: proposed
date: 2026-09-20
author: Lead（Owner 2026-09-20 指令：单独验证 llm 与 backend 的能力；两层有机配合）
review: 设计经两席专项咨询 —— auditor `run_20260920103042995fk9p1i`（D1–D6 设计）
        与 coder_mm `run_20260920103042191yn2ln1`（D1–D6 设计）；分歧点由 Lead 裁定，见 §4。

## Context

**Owner 指令（权威）**：WAO 需具备**单独/分别验证 llm 与 backend** 的能力；**组合能力验证是一层，
组件（llm / backend）能力验证是另一层**，两者要有机关联。验证某组件时应**装配现成可用的另一侧**做夹具。

**现状痛点**（两席一致）：
1. 新 backend / 新模型**没有廉价预筛**——只能靠"装配一条 lane 并跑组合认证"。
2. 组合认证红时**难以归因**（是组件坏还是交互坏）。
3. **零目标假绿**：`--agent <lane>` 无矩阵行 → 零 case → 仍报 `ALL PASS` 且 exit 0
   （实证：`coder_low_dsh` 认证"通过"但无任何 case 与认证记录）。

**既有裁定的关系**：ADR-0025 #6 曾禁"模型池 / 模型级认证"，其**测量学命题**（认证测的是
harness × 模型 × 角色合同的**交互**）**仍然成立，保留为语义防火墙**；本 ADR 只澄清其**适用面**。

## Decision

### 1. 词汇与状态闭集**分层**（不是措辞问题）
- 组合层：`certified` / `conditional` —— **独占**，延续 ADR-0025 #5 零改动。
  【已核验】这两个词已被门与 wire 加载（`DISPATCHABLE` 集合、`buildCertMap` 投影），
  **复用即语义泄漏**。组件层代码**不得 import** `scripts/reliability/certification.mjs` 的状态闭集。
- 组件层：`pass` / `fail` / `blocked` 三值闭集。文档形容词：LLM = **verified**；
  backend = **conformant**（**必须附合同名称与版本**）。

### 2. 两层各测什么
| 层 | 专属断言 |
|---|---|
| **LLM** | 动态读取+结构化回答（从**工具结果**取随机值，不能只在回包里搜到）；工具使用与结果理解（非零退出不虚报成功）；有界任务完成；指令与角色约束（**角色自述只证明收到提示，不证明胜任**）|
| **Backend** | 启动与配置传递（不支持参数**明确拒绝，不静默忽略**）；事件与证据转换（缺字段/乱序/重复/断流**不能制造成功证据**）；生命周期；**能力声明 ⇔ 实测一致性**（声明 `reportsTokenUsage` ⇔ input token 非空；声明 `supportsSessionReuse` ⇔ 实际 resume 行为）|
| **组合** | 角色任务闭环；隔离与交付；实际运行路径（**不能由别的装配结果替代**）|

**专属边界**：进程清理**不是**模型能力；任务答案对**不证明** backend 机械路径对；
共有观察可支持不同断言，**结论不得互换**。

### 3. "有机配合" = 证据复用，**不是绿灯传递**
- **推导闭集**：组件绿 + 组件绿 **⇏** 组合绿；**组合绿 ⇒ 该次运行的组件观测事实可顺带双记账**
  （一次 token，两个判定——这是"有机配合"的核心机制）；组件红**不阻断组合**，但触发 advisory
  （**新鲜度分叉 = 认证后回归信号**）。
- 组件层三个真实用途：① 入册前**廉价预筛**（比全 lane 认证便宜一个量级）；② 组合红时**故障归因**；
  ③ backend/parser **回归金丝雀**。

### 4. 夹具机制（Lead 裁定，见 §4 分歧）
- 验 backend → 挂**现成可用模型**；验 LLM → 挂**有可追溯成功证据的 backend**。
- **夹具资格依据 = 新鲜的组合认证记录 _或_ Owner 显式指定的参照装配**（二者任一）。
  ⚠️ **不要求"必须先有已认证 LLM"**，否则形成**启动循环**。
- 夹具指定为 **Owner 配置**（`certification.fixtures` 声明块），**不硬编码**。
- **夹具必须入账**：记录显式分 `subject` 与 `fixture` 两字段；fixture 记全身份四元组 + runtime/适配器版本
  + 配置/合同摘要 + 环境 + 实际 runId + 资格依据。
- ⚠️ **不得复用组合的 `certifyCase()` 给组件盖章**。

### 5. 台账：**分文件、共证据**（默认安全）
- 组合台账保持 `runs/reliability-summary.json`；组件台账新增 `runs/component-checks.json`。
  【已核验】前者的 `workers` 映射被门（`runManager.js:1237`）与 `buildCertMap`
  （`registryInventory.js:123`）**直接消费**——同文件须在每个消费侧加过滤，**漏一处即泄漏**。
- 组件文件**不写** `workers`、不写组合 `status`/`recommendedUse`/`lastFullHealthyRunAt`。
- 身份键走 **kind 命名空间**：`backend:<name>@<codeRef>` / `llm:<providerID>/<modelId>@<providerKey>`；
  `codeRef` = 验证时 WAO repo 的 git HEAD。与 ADR-0026 四元组（活在 `workers` 映射）**键空间不相交**。
- 时间字段 **`lastVerifiedAt`** —— 绝不用 `lastHealthyRunAt`/`lastFullHealthyRunAt`
  （`runManager.js:1254` 的 legacy 回落只认这两个名字，新名字**天然隔离**）。
- **消费路径六态**（逐一处理）：`normal` / `ledger missing`（显示"未验证"——**不是红也不是绿**）/
  `unparseable`（**显式报错，不静默跳过**）/ `stale`（codeRef 不匹配或超期 → advisory）/
  `blocked`（夹具不可用）/ `fixture-decayed`（夹具认证过期 → 历史组件记录全部降 advisory，不删）。

### 6. 机制
- 抽 `scripts/reliability/drills.mjs` 导出 drill glue，两入口共用——**防双轨漂移的必需品**。
- 新入口 `scripts/run-component-check.mjs` + npm script `component-check`（经 `wao-node.cjs` 转发）。
- **复用 `--registry`**：临时生成只含夹具装配的 registry，agentId 用 `_fixture_backend_<name>` /
  `_fixture_llm_<id>`。**不动** `config/agents.json` 的 `certification.matrix`（那是组合层 lane 的 SSOT）。
- **消除账实不一致**：`matrix.mjs::normalizeCase()` 现允许矩阵的 `providerID/modelId` **覆盖** agent 配置，
  而 runner 按 agentId 派发、按矩阵值记账 → 必须消除该路径。

### 7. 前置根修（先于一切）
两个入口在目标解析后**断言 ≥1 case，空集 exit 2**；零目标 / 未知 profile / 无有效 drill
**在创建临时文件、派发、更新 summary 之前拒绝**；输出本轮 `selected/executed/passed/failed/skipped`
计数，历史台账另列；**只有 skip 的运行不得报 `ALL PASS`**。（顺带偿还 TD-133(e) / TD-169(b)）

### 8. 五态检查结果（防"跳过算通过"）
`pass` / `fail` / `not-applicable` / `blocked` / `inconclusive`。
**N/A 必须有原因且不贡献能力绿**。现存坏模式必须修：`metricsNonZeroCheck()` 把不适用记为
`pass:true, capability:"metrics"`；silentTimeout 在 serve 不可达时写通过；
`hasSentinel()` 搜所有 message；`runStrictScorecardDrill()` 只查文件存在不查内容；
`scorecardChecksFromResult()` 缺 scorecard 时用 `completed` 顶替证据检查。

## §4 分歧与 Lead 裁定
【分歧】夹具资格：auditor 主张**不强制**先认证（否则启动循环）；coder_mm 主张夹具**须**有当前新鲜的
组合认证记录，否则 `blocked: fixture-unavailable`。
【裁定】**取 auditor 方向 + 吸收 coder_mm 护栏**：夹具资格 = 新鲜组合认证记录 **或** Owner 显式指定的
参照装配；后者落在 `certification.fixtures` 声明块（不硬编码）。既无启动循环，也不允许"随便抓个能跑的"。

## Consequences
- **registry schema 与 MCP 面零改动**；新增一脚本、一台账、若干 drills 与测试。
- 组合认证仍需实际运行；组件通过**不替代** ADR-0029 #1/#3 的承重义务。
- **不设**自动路由、额外默认门禁、runtime 安装修复责任。
- 首期不为组件层建模型池：组件层是**诊断/初筛语义**，不进门禁、不进 wire 投影、不自动续期任何东西。

## 修订（2026-09-22，Owner 裁定：认证证据详情按需进入 MCP 只读面）

**背景**：本 ADR 原写「组件层首期不进门禁、**不进 wire 投影**」。2026-09-22 Owner 采纳 auditor 咨询裁决
（`run_20260922163825066wnej8s`），把"某席位的历史认证证据是否适用于当前配置"这一判断按需开放给 MCP Lead。

**决定（Owner 原话裁定文本）**：同意把认证证据详情通过 `registry_list` 的显式详情选择开放给 MCP，仅供 Lead 判断；
保持 MCP 的 `requireCertified=false` 与 CLI `--require-certified` 原语义，任何将其变为派发门禁的提议另行裁决。

**边界（与上文"不进门禁"一致，仅放宽"不进 wire 投影"这一条）**：
- 只读、按需（默认简表 `agents/issues/issuesTruncated` 一字不变）；不新增工具，维持 22 工具闭集。
- 保持分层与 advisory-only：组件通过不推出组合绿；**"无法判断"不算绿**；不得派生"总体可用=true"。
- 两本台账的来源状态（缺失／不可解析／读取错误）、三态适用性（匹配／不匹配／无法判断）必须分别可见，MCP 投影不得丢语义。
- 工具面体积须实测并说明必要增量，不得为转绿放宽既有守卫上限（整体 78127 B／描述 11225 B）。
- 止损：若实现需新增工具、改认证门禁、自动探测或重认证，或为控体积丢弃"限制与来源" ⇒ 暂停重新定界。
