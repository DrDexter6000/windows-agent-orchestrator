# 0029: 认证两段式入册与突发迁移（修订 0025）

status: accepted
date: 2026-09-17

## Context

2026-09-17 三条 lane 在一日内突发切换：claude 订阅取消 → auditor 换 backend（claude-code → codex/GPT-6-astra）；DeepSeek 欠费停用 → researcher/coder_low 换 provider/model（→ 智谱 glm-5.3-flash[1m]）。切换当日各 lane 均做了 smoke 首跑（端到端连通 + 角色合同自检，completed），delta 认证随后补跑。

这暴露 0025 两处条款与现实的张力：

1. **0025 #3"未付认证费的组合不进 registry"**在供应商突发死亡（订阅取消/欠费停服）场景下，把 Owner 卡在"席位瘫痪等认证"与"违反纪律先入册"之间二选一。一条在紧急状态下必然被违反的纪律，就是一条正在被腐蚀的纪律。
2. **0025 #2"新旧 harness 禁止原位换"**未区分两种场景：双活切换（新旧 harness 都活着、要可来回切——禁止原位换的理由成立）与死通道迁移（旧 harness 已死，"并存"不可能，串线面不存在）。

双席咨询（auditor run_20260917164247217hi81oq / coder_mm run_20260917164249776nsqy6t，2026-09-17）一致结论：保留认证机制、取消定期全量重刷、"按需"须明文档位规则；轻量认证档已存在（delta profile），smoke 首跑不得写台账。Owner 同日批准两段式修订与以下全部条款。

## Decision

1. **#3 修订为两段式**：入册允许先行（尤其供应商死亡类突发），两个硬约束随行：
   - (a) **切换当刻必须 smoke 首跑**（小任务端到端自检：读文件 + 角色合同身份自述 + 通道结论）。smoke 是地板不是认证：只证连通与角色注入，不写台账、不产生任何认证声称（不发明第三档 scope——delta 即轻量认证档，0025 #5 原文已立）。
   - (b) **承重前必须补 delta 认证**（该 lane 第一个真实交付任务之前，或需经 `--require-certified` 使用时）。台账身份比对 fail-closed（TD-131/132/136：backend+modelId、per-worker 新鲜度、providerKey 指纹）保证入册先行不可能洗白旧记录。
2. **#2 适用面澄清**：禁止原位换针对**双活切换**；旧通道已死（订阅取消/服务商停服）时 Owner 可裁定**原位迁移**，条件：会话复用机制随迁移重估（auditor 切 codex 已移除 sessionReuse），认证历史作废重跑（身份比对自动失效，不残留误导）。
3. **取消定期全量重刷**。刷新触发面（闭集）：改配置（model/provider/backend）｜证据解析或完成判定逻辑改动｜真实回归事件（TD-147 类）｜将再次依赖已过期认证。档位规则：同 backend 换 model/provider → delta；换 backend 或 lane 升主力 → 全量。delta 不洗白 `lastFullHealthyRunAt`（ADR-0026 设计不变）。
4. **门禁维持 opt-in**（ADR 0018 不动）。默认开启的判据 = 出现"无 Lead 在环的派发面"（现状不存在；若未来出现按面开，不全局翻默认）。

## Consequences

- 本周三 lane 切换按新纪律回溯合规（smoke 已做、delta 同日补跑；auditor 原位迁移按条款 2 成立）。
- 认证纪律的档位规则表与触发面随 TD-161 (b) 接入食谱节写入 `docs/usage.md`（本 ADR 是权威，usage 只写指针+操作表）。
- 0025 原文不动；与本 ADR 冲突的条款（#3 入册前提、#2 原位换禁令的适用面）以本 ADR 为准。
- 真实任务证据可用于减少无目的复测（advisory 判断），但不得自动续期任何认证能力面（auditor 咨询结论）；"生产健康投影"作为研究方向另行登记，不进台账。
