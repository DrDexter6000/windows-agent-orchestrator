## §1 机制

- **登记册**：`test/interference-registry.json`（committed、套件只读、Lead 独占编辑权）。条目=id/file/subtest/signature（归一化错误文本：数字串→`<n>`，字符串全等，**禁 regex**——套件既有禁令 no runtime regex classification）/isolationRequired:true/registeredAt/**expiresOn**（登记起 ≤14 天）/owner/note/status（active|expired|superseded）。
- **资格闭集**（全部满足才允许自动裁定，缺一即整文件回 fail）：
  1. 首轮 fail 且隔离复跑 pass（既有 classifyIsolation 产物）；
  2. failureDetail 完整：status≠unknown、失败子测数≤FAILURE_DETAIL_TEST_CAP、无 TRUNCATED 标记；
  3. **每一个**失败子测试都命中同一条 active 条目（防同文件真缺陷被搭车洗白——opus 必改）；
  4. **非 worker 上下文**（WAO_IN_WORKER=1 或 cwd 在 .wao-worktrees 内 → verdict 恒 fail，只打 advisory"本应命中 <id>"——防 worker 交付给自己加条目自我洗白，opus 必改）；
  5. 条目未过期（expiresOn 依当日日期）。
  - **P4 会审补强（B2，opus）**：文件级失败在场（fileFailure≠null）或 fileFailureDropped=true 一律不裁定——挂死的子测不进 tests[]、唯一信号是文件级 test:fail（reporter.mjs:36-41），不检查则"命中签名的子测+未登记的挂死子测"可被搭车洗白。同文件级字段携带 TRUNCATED 同样拒绝。
- **效果**：verdict=pass + test-results.json 标 `auto_adjudicated:[{id,subtest}]` + 控制台响亮行（"绿灯来自登记册，非代码正确性证明"）+ 汇总行带 `auto_adjudicated=N`。首红原始记录永不删除。
- **衰减=expiresOn 日期**（opus 设计，取代"连续 N 次命中"计数——后者前提不成立：realDeleteReport 首波即删上一次结果文件，计数系统性丢失）。日期在提交文件内、只会往严的方向变（到期→自动回 fail+响亮提示），不造假 pass。失效动作=Lead 显式编辑提交（status→expired 或删除），套件绝不写仓库文件。

## §2 红线级变化（显式记录）

1. **"isolation never washes green"不变量修订**：由无条件改为资格闭集条件下允许 wash。canonicalRunner 元测试相应重钉（双向：资格齐全→wash 且带标记；缺任何一项→恒 fail）。
2. **verdict 依赖时钟**：expiresOn 与当日日期比较——同日确定，跨 expiry 边界两日结论不同。这是本决定显式接受的确定性让步（换取登记条目自动过期，防僵尸豁免）。
3. **不变**：套件不写任何仓库文件；首红原始记录不删；worker 上下文禁用；CLI/动词面零变化。

## §3 边界与不做

- 不做"复核提醒"型跨跑计数（realDeleteReport 语义下无处可读，见 §1 衰减说明）。
- 不迁移历史假红豁免标签（TD-242 治理教训：基线豁免须精确到测试名+失败签名——本登记册正是该形态的机器化）。
- 治根优先于登记：凡能改稳的测试先治根（本批 runsVerifyCommit 643 已治），登记册只收环境互扰类。

## §4 验收

- 元测试重钉 + 资格闭集逐项反例（缺一项即回 fail）+ worker 上下文关闭钉 + 过期回 fail 钉 + 归一化函数钉（含禁 regex 的实现形态）。
- dogfood：一次性 worktree 受控演练（真"首红+隔离绿"夹具+临时 active 条目）+ 主仓 git diff 干净核实 + 全量零假阳性 auto_adjudicated。
