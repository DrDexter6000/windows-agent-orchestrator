## 背景

- 项目身份按 cwd 的规范路径算：分隔符归一、realpath、Windows 大小写折叠；路径里的 `.wao-worktrees/<run>` 段回溯到所属仓根（R4）。
- `git worktree add` 建的链接工作树有自己的路径，于是自成一个项目。WAO 开发每批一棵，桶随批次增长；别的项目用链接工作树也一样。
- 新运行的首事件写下归属事实（key、bucket、rulesVersion），读侧以在档事实为准，没有事实的旧运行才从 cwd 推导。

## 决定

1. **链接工作树归主工作树（R8）。** R7（沙箱）与 R5（临时目录）照旧先判。R3 的 realpath 与 R4 的重放之后，若该路径是一棵工作树的根（它的 `.git` 是文件），按 git 自己的读法找主工作树：
   - `.git` 文件的内容是 `gitdir: <路径>`，去掉行尾的 CR/LF；相对路径以工作树根为基准；结果做 realpath。
   - 这个目录下的 `commondir` 文件（同样去掉行尾 CR/LF）指向共同目录；相对路径以上一步 realpath 之后的目录为基准；结果做 realpath。
   - 共同目录的名字是 `.git` 时，主工作树是它的父目录，与 `git worktree list` 第一行报告的路径相同。这个路径只做大小写折叠得到 key，displayName 取它的目录名，不再重判 R4、R5、R7。
2. **读不出就照旧。** 只读这两个小文件，各有字节上限，不起 git 子进程。任何一步读失败、超上限、内容形状不对、没有 `commondir`（主检出、子模块、`--separate-git-dir` 的主检出、admin 目录已被 prune）、共同目录不叫 `.git`（常见的裸仓库 `x.git`、子模块自己的链接工作树），或者 realpath 失败，结果都与不加 R8 时相同：不报错，也不变成 unattributed。
3. **只看工作树根。** cwd 是工作树里的子目录时不往上找，与现有规则一致；`<工作树>/.wao-worktrees/<run>/…` 先经 R4 回到工作树根，再经 R8。
4. **文件只经注入的 io 读。** 身份判定保持纯函数。`productionProjectIo()` 提供读文件函数，没有注入时 R8 不生效。自己拼 io 的调用点（`bucketCandidateFromCwdHint`、迁移计划器与执行器）原样转交这个函数，所以写侧、读侧、计划器对同一个 cwd 得到同一个 key。
5. **规则版本升到 `td190-r3`。** 新运行的归属事实记新版本。有在档事实的运行不重推，留在原桶。没有事实的旧运行在 `runs list --project` 与迁移计划器里按新规则推导；本机存量里没有这类开发树运行。
6. **已有的开发树桶不迁移。** 树删了、运行全部收口后，按 Owner 授权归档到 `runs-archive/<月>/projects/`。

## 否决的备选

- **按 `.dev/wt/` 路径词法剥离**：只对 WAO 自己的目录约定有效。
- **起 `git rev-parse --git-common-dir` 或 `git worktree list`**：身份判定在派发与读侧都会跑，每次多一个子进程。git 算主工作树的办法就是共同目录去掉 `/.git`，读两个文件得到同一个答案，拿 git 兜底也不会得出不同的结果。
- **核对 admin 目录里的 `gitdir` 回指**：git 在工作树里干活时不看它。加上之后，复制或手工挪动过的工作树会与 git 的判断不一致。
- **把开发树 key 登记为主桶的别名（`.project.json` 的 `aliases`）**：要改主桶记录，换来的只是 `--project <开发树路径>` 仍能选到旧运行；旧开发树桶本来就在归档。
- **只提高扫描上限**：不消除增长源。
- **把已有开发树桶迁进主桶**：要改在档事实与桶记录，换来的只是历史运行换个目录。

## 已知边界

- 名叫 `.git` 的裸仓库（`git clone --bare <url> proj/.git` 后再加工作树），它的工作树都归 `proj`。`--separate-git-dir` 指向一个名叫 `.git` 的目录时，链接工作树归那个目录的父目录，主检出仍归它自己。两种情形都与 `git worktree list` 报告的主工作树路径一致。
- `.git` 文件指向哪个仓库，运行就归哪个仓库，git 在那里操作的也是那个仓库；复制出来的工作树目录归原仓库。桶不是安全边界，MCP 的归属核验按运行的 cwd 比对绑定根。
- admin 目录被 prune 而树还在时，新运行回到按自身路径归属。
- 绑定在开发工作树上的 Lead，`lead_preflight` 与 `runs_list` 显示的项目标签、反馈条目记下的项目标签都是主项目的。`runs_list` 的结果仍只含按 cwd 归属核验通过的运行，标签与取数范围不一致。在主检出绑定的 Lead 仍读不了从开发工作树派出的运行（TD-324）。
- `runs list --project <链接工作树路径>` 选的是主项目。R8 之前按工作树自身 key 记下事实的运行，要用它的裸名或 slug 选。
- R8 之前从开发树派出的父运行在开发树桶里，之后续跑出的子运行进主桶；按 runId 的解析照常找得到两者。
- 子目录 cwd、非 Git 目录仍各自成一个项目。桶数超过扫描上限时，新派发与没有快速命中的读写照样失败（TD-325）。
