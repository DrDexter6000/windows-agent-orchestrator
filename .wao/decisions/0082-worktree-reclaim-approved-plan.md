## 背景

- 隔离运行的树与 `wao/<runId>` 分支只有三条自动回收路径：
  - 只读运行停止确认后释放（0057 W1a），零独有分支随之回收（0062 丙′）；
  - 交付 accept 释放线系树（0057 W1b）；
  - `runs lineage-close` 释放树，分支永不删（0058）。
- 其余一直留着：reject 和 failed 的交付、普通隔离运行、早于这些机制的历史运行。
- 2026-10-15 普查：
  - WAO 仓：44 条分支；
  - 一个文档型宿主仓：115 条分支、109 棵在册树，抽样估算约 3 GB；旧副本还会被检索工具扫到。
- 清退靠手工规程和 `.dev/` 下的一次性脚本。规程允许"已拒绝的分支 bundle 后删"，0057、0058、0060 却写着交付分支永不删，两边互相矛盾。

## 决定

1. 存量清退走 `wao worktree reclaim`，四步：
   1. 生成计划（只读）；
   2. Owner 按计划的 sha256 点名批准；
   3. `--apply <plan> --expect-sha256 <hex>`，只执行这份计划；
   4. `npm run hygiene`。

   批准计划就是语义判断（"这条线系已放弃"），仍归 Lead 与 Owner，不会自动发生。
2. 分支可删的条件，两条都要满足：
   - 它在 Owner 批准的计划里；
   - 它的 tip 在本次清退已验证的 bundle 里：完整历史，`git bundle verify` 通过，`list-heads` 含该 tip。

   删除用比较后删除，即 `update-ref -d <ref> <计划 tip>`，ref 变了就不删。
3. 0057 的"rejected/undecided 交付分支仍永不删"、0058 的"分支永不删"、0060 的"非交付遗留树分支永不删"，都改为"除按本决定经批准的清退外不删"。
   - 0060 的"只读 run 分支例外"（Lead 手动删零独有且 tip==main 的只读 run 分支）也只走批准的计划，这是收紧。
   - lineage-close、accept 释放、只读释放本身的行为不变：前两者仍不删分支，只读释放（0062 丙′）仍自动回收零独有分支。
4. 终态的零丢失自动回收（TD-146 原条目的候选 (c)）不在本决定内，另议。
5. 清退产生的 bundle 不删，要删须 Owner 批准。
   - `runs-archive/` 只在本机，`wao/*` 从未推到远端，分支删掉后 bundle 是唯一副本。
   - 每次清退的记录目录（计划副本与逐项结果）记着分支名、tip 与 bundle，就是取回所需的索引。取回一条分支：`git fetch <bundle> refs/heads/wao/<runId>:refs/heads/wao/<runId>`。
6. 批准删分支不等于批准丢弃脏树内容。计划里标"删除即丢弃未提交内容"的项，Owner 批准时须逐项明示同意；有不同意的，这份计划不批。
7. 每批收尾不删本批的交付分支，交给定期的清退计划，与存量一起处理。

## 否决的方案

- **按龄或按量自动淘汰**：0057 已否决，已放弃与否是语义判断。
- **只删零独有分支、不做保全**：两条待删分支互相覆盖同一个别处没有的提交时，按"零独有"都不保全，删完提交就丢了。这是会审给出的反例。
- **继续手工规程加一次性脚本**：每次都要重写，批准的清单与执行的动作没有绑定。

## 已知局限

- 内容指纹对未跟踪与被忽略的文件只记路径、字节数、mtime，不逐文件哈希。
- bundle 是完整历史，每次清退约十到数十 MB。
- 已裁决或线系已关的运行，树脏时按放弃处理，删除即丢弃未提交内容。计划里逐项标明；记录只存路径清单，不是内容备份。
- detached HEAD 或换了分支的树一律保留（`head_drift`）：bundle 只收分支。
- 宿主仓是否清退、何时清退，由 Owner 决定。
- 分支删掉、提交被 gc 回收之后，这条运行不能再 `runs verify-commit`、repackage 或续接：三者都明确拒绝，不会从 main 重建（`test/delivery/td146ReclaimedRunEntryPoints.test.js` 钉住）。纠偏只对在跑的运行有效，清退不收在跑的运行，不受影响。
- 2026-10 各批收尾时，Lead 曾在 bundle 校验后删掉本批交付分支（11 个 bundle 在 `runs-archive/2026-10/delivery-closeout-*.bundle`），与 0058 不符。这是历史偏差，本决定不追认；这些 bundle 同样按第 5 条保留。
