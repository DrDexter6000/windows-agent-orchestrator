## 背景

车道型号除了写在配置里，还写在现行文档、模板注释和测试字面值里，没有任何东西核对。型号升级后这些副本悄悄过时；模板与车道表之间的型号也不比值。

## 决定

1. **只写在配置里。** 车道当前型号只出现在：
   - `config/lanes.json` 与 `config/agents.example.json` 的 `model.id`；
   - 认证矩阵的 `modelId` 与 `label`。
2. **守卫（`docs-consistency.test.js`）。** 现行文档与模板里 `_comment*` 字符串不得出现当前车道型号。
   - 集合由 `config/lanes.json` 现算：取完整 id 与最后一段，与车道名同名的跳过；
   - 匹配大小写不敏感，按完整 token。
3. **具体型号的事实原样保留。** 上游报错原文、某个型号的行为这类内容，放在 `<!-- model-specific -->` 与 `<!-- /model-specific -->` 之间，守卫跳过。
4. **配置内部的副本由关系检查守着。**
   - 模板条目的 `model.id` 等于车道表；
   - 认证矩阵的 `modelId` 等于 agent，`label` 含 agent 的型号；
   - 测试里的型号字面值钉改为上面的关系检查，只留 deepseek-flash 的视觉档策略钉（0046 §1）；
   - 需要与在库车道数据对上的测试夹具（别名解析、显式派发）从车道表取接线，不写型号字面值；
   - `dispatchResolution.test.js` 的 W3a 映射快照和 W1 读的入库夹具 `test/fixtures/lanes-agents.fixture.json` 照旧写当前型号：它们是有意的同 diff 审查点，改绑或升级型号必须一起改。
5. **升级型号时会发生什么。**
   - 文档里本来就没有当前型号，不用改；
   - 配置里没跟上的副本，在同一批改动里变红：模板与车道表的关系检查、W3a 快照、W1 夹具的跨文件校验，模板跟上之后是认证矩阵的关系检查；
   - 新型号如果已经在文档里作为别的事实被提到，守卫在改配置的同一刻点名，由 Lead 改写或加标记。

## 否决的备选

- **文档里的型号必须能在模板里找到（Owner 原话）。** 二十多处写的是别的路径的示例或具体型号的事实，要开例外名单。
- **文档里禁止一切带版本号的型号，加就地标记（sol）。**
  - 要人手维护一份厂族正则；
  - 今天就得标约 20 处，以后每条与型号有关的排障都要标；
  - 多出的保护是"新写错一个旧型号"，那是写错，不是过时。
  - 它的就地标记被本决定采纳。
- **只禁当前型号、不加标记（deepseek-flash）。** 车道换上一个文档里描述过的型号时，守卫会逼着有损改写恰恰最有用的那句。
- **退役名单。** 靠人记得加。
- **从 git 历史推退役型号。** 测试依赖 git 历史，浅克隆或改写历史都会出问题。
- **生成一页车道→型号表。** `wao lanes` 已经现场显示型号。

## 已知边界

- 新写进文档的旧型号或从未用过的型号不会被抓：那是写错，不是过时。
- "K3""GLM-5 系"这类散文叫法不在 token 匹配范围内。
- 只改私有注册表、没改 `config/lanes.json` 时测试不红；派发时注册表与车道表不一致即拒。
- Owner 撰写的画像文本（`config/lane-traits.json`）不在扫描范围，画像的新鲜度以重认证为准。
- 代码里的注释与报错示例不在扫描范围；生成层的源字符串经生成物被扫到。
- `config/lane-exceptions.json` 的例外按车道四元组（含型号）登记。型号一换，例外不再命中，车道的认证判定回到未豁免状态：在 `wao lanes` 与 `registry_list` 的认证栏可见，没有测试变红。例外随重认证重新裁定，这是有意的。
