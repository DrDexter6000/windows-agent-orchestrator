# 0133 带交付的后台派发默认可续修

- 日期：2026-11-27
- 状态：accepted
- 来源：Owner 2026-11-27 问"既然可续修这个选项很容易遗忘，要不要在 wao 机制中默认开启"；Lead 核对事实后建议开启并说明条件与回显，Owner 未反对，按 /goal 推进。第 154 批（sonnet 实现，sol、deepseek-flash 会审）。
- 关系：取代决定 0112 第 3 条（`continuable` 默认值不变）；续谱机制（M12-7、0114）与 `run_continue` 资格检查不变。

## 背景

0112 否决默认开启，理由有三：一是派发侧不是瓶颈，Lead 已常带；二是默认值要随后端能力变；三是 Lead 从参数上读不出这次能不能续。

此后的事实：
- 11-04 至 11-27，各项目带交付的派发里，带 `continuable` 的有 264 个、不带的 36 个，续修用了 267 次；可续是常态。
- 11-27 第 145b 批 3 次派发漏了 2 次。其中一次因此续不上，只能新开会话重读材料；另一次跑了一分钟才发现，停掉重派。
- 五种后端都声明了 `supportsSessionReuse`。

## 决定

1. **三态。** `continuable: true` 显式开，做不到照旧按具名错误拒绝；`false` 显式关；缺省为自动。
2. **自动开启的条件。** 带交付的后台派发，下列条件全部满足才开：
   - 有绑定工作区，且能证明它是 Git 顶层（与 `run_continue` 同一个证明函数；子目录、非 Git 目录都按 `no_workspace` 关闭）；
   - 没有按次的 `model`/`reasoning` 覆盖（它们与谱系互斥）；
   - 后端声明 `supportsSessionReuse`；
   - 后端说当前环境能建立会话复用（`sessionReuseUnavailableReason()` 为 null；claude-code 没有长期令牌时为 `token_required`）；带上谱系参数后 runner 参数预算与后端的 worker 启动预算（含 `correctable` 参数）都不超限；谱系槽可用（不忙、存储可写）。预算先做预判，以真实检查为准：写槽之后真实检查超限、或 runId 仲裁拒绝时，自动模式按内容撤回自己的槽，改按不可续照常派发。

   任一不满足就静默关闭，派发照常，与非续修派发逐字节相同；所有判定都在写谱系槽之前。自动关闭不能把原本能派的任务变成派不出去或启动后才失败。能力判定用已构造的后端，不看调用方是否传了能力解析器。谱系身份用证明过的工作区根，首轮与 `run_continue` 同源（以前相对路径、目录名大小写、junction 时两边对不上，claude-code 会 `--resume` 到不存在的会话）；这同样适用于显式 `true`，它对非 Git 顶层的工作区改为派发时就拒绝。
3. **回显。** 派发结果带 `continuable`（布尔）。缺省下带交付却没开成时，再带 `continuableOff`，取闭集 `no_workspace | override | backend_unsupported | session_reuse_unavailable | argv_budget | lineage_slot_unavailable`（顺序即判定先后）；CLI 前台另有 `foreground`。Lead 读结果就知道能不能续，不靠记参数。
4. **CLI。** 交付规格顶层的 `continuable` 同样三态；写成非布尔值（`"false"`、`null` 等）时按显式关闭处理：既不反转意图，旧规格文件也照旧可用。前台 CLI 不能建谱系：缺省时静默不开；显式 `true` 照旧报错。

## 否决的备选

- **硬默认 `true`（做不到就拒绝）**：没有长期令牌的机器上，每次 claude-code 交付派发都会被拒；带覆盖的派发也会被拒。
- **只在文档里提醒**：0112 已经这样做过，11-27 仍连漏两次。

## 已知边界

- 显式 `true` 遇到没有令牌的 claude-code 仍照旧受理，到 spawn 时失败（行为不变）；只有自动模式会预判、会撤槽。
- 预判在 Windows 上可能起只读的 `where` 查找进程（至多两次）；极端情形下自动模式先写再撤一次槽，可能留下空的 `.lineage-reuse` 目录。
- 可续的谱系会保留 provider 会话；claude-code 另有一个稳定会话目录，由清扫按最近使用时间删除。
- 派发到 runner 起动之间注册表或角色正文变了，runner 以 `reuse_material_mismatch` 失败（fail-closed）；这个窗口以前只对显式续修，现在覆盖所有自动开启的交付。
- 每个可续根在 `.lineage-reuse` 留一条槽记录，不清扫；派发后 5 分钟内关闭该谱系会判忙（TD-383）。
- 第三轮复核（sol）余下的边缘情形按决定不再修，记入 TD-383：长度恰在预算边缘的派发因预估偏大不开续修（派发照常）；同一自定义 runId 并发派发时撤槽可能删掉对方的槽；撤槽本身失败时留下一条槽记录；首次建槽目录时与并发调用的微秒级竞态会删掉对方刚建的空目录；底层读文件的编程错误被当成存储错误。
- MCP 工具面 wire 冻结线随输出形状重冻（记录见决定 0021）。
