## 背景（2026-10-12 实测）

- **转录普查**（主检出 `runs/`，109 次 zcode 运行）：12 次被停滞门判 `turn stalled`。其中 7 次死时有工具调用在途（`npm test 2>&1 | tail -12`、等后台任务输出的 `TaskOutput` ×3、`git diff --stat …` 等），5 次死在模型长思考中。
- 同日上午加的流证词只覆盖后一类（模型在出 token）。工具命令在跑时模型不出 token、快照不长 part，流证词帮不上。
- 流证词自带硬顶（先是每 turn 累计 30min，当晚改为自上一个 part 起 120min）：流还活着也会被控制面收掉，与 Owner 的裁定相悖。
- `wao stop` 对 zcode 运行不生效（TD-265）：Lead 即便决定放弃也执行不了。
- **进程活跃度真机探针**（`run_202610121926214595bjyas`，glm-flash，依次跑 `sleep 40` 与 30s 忙循环；约每 6s 取一次 app-server 后代快照，后代 21–25 个进程）：

  | 阶段 | 后代 CPU | 后代 I/O | 进程生灭 |
  |---|---|---|---|
  | `sleep` 期间（空闲） | 0–2.5 ms/s | 4.2–8.7 KB/s | 无 |
  | 忙循环 | ≈990 ms/s | ≈4.6 KB/s | 无 |

  宿主进程自身因控制面每拍经 stdio 取快照而 I/O 恒涨，不能作证——只看后代。

## 决定

1. **收口归属**：控制面只在运行没有任何生命体征时自动收口；有生命体征的运行不因"等不到进展"被收掉，去留由 Lead 决定，控制面只提供事实与建议。本决定落在 zcode 后端。
2. **zcode 的生命体征**（任一成立即不收口）。三道"等不到进展"的门——零 part 阶段的 silentTimeout 与 120 拍思考预算、已有产出后的停滞预算（300–600s 自适应）——到点时都先看：
   - **进度**：快照落了新 part，或既有 tool part 原位落了新证据（工具调用的开始 / 结束）；
   - **流分片**：最近 60s 内收到过该会话的模型流分片；
   - **进程活动**：取一次 app-server 后代进程快照，30s 后再取一次——窗内后代 CPU ≥20 ms/s，或 I/O ≥64 KB/s，或有进程新生 / 退出（同一 pid 的累计读数回退按"换了进程"计）；
   - **工作树变化**：同一 30s 窗内，工作目录里已改动 / 未跟踪文件的清单、mtime 或大小变了（输出交付物）。

   都没有 ⇒ 收口，错误文案写明取到的读数。后两项只在门到点且流不在收时取证；比对得出"没有活动"后不当拍收口，先记下事实，下一拍照常轮询一遍仍无进展才执行（取样占用时间，其间可能来了流分片或落了 part）。
3. **让 Lead 看得见**：流在收时每 60s 向转录发一条零载荷的 `runtime_activity("streaming")`（既有闭集；零新事件类型、零 wire 变更），等待类命令据此显示 `liveness=progress` / `lastActivityKind=runtime_status`。CLI `status` 在未终态且转录里 ≥30 分钟没有新的动作或正文时附 `advisory` 一行（多久没有、最近活动、中止命令；读时推导，转录零写入）。
4. **让 Lead 停得掉（关 TD-265）**：会话 id 是 provider 原生 id 的本机进程式后端在 spawn 结果里报 `hostPid`，RunManager 记入 `session.created`；resume 以新进程重放时记入 `run.rerun`。stop 按会话记录的事实选路由（`proc_<pid>` 占位 id 或 `hostPid` → 进程树击杀并核验；`serveUrl` → 服务端中止），不按后端名分支；重放之后目标取重放记录的新会话与新进程（此前——含 `proc_<pid>` 路由——仍指向已被替换的旧进程）。无路由时报错点名后端。
5. **TD-180 落 A**：不自动重试。`runs diagnose` 对"进程退出前零 worker 事件"的崩溃另列一条观察事实——只陈述事实，守诊断模块"给证据、不给处方"的铁律；既往案例与处置经验写进 `docs/troubleshooting.md` §7.15。
6. **不变**：MCP 工具面零触碰；没有新增转录事件类型；停滞预算本身（300s floor / ×3 / 600s ceiling）与 60s 新鲜度窗不变；取证只在"原本要收口"的那一刻发生，不进常规轮询。

## 诚实边界

- **"没有自动上限"只指这三道"等不到进展"的门。** 协议错误、传输关闭、轮询失败、快照缩短、历史变异这些"证据归属不可信"的失败，以及预算与隔离守卫，照旧立即收口，不看生命体征。
- **证词可能把不在推进的运行读成"活着"**，而删除硬顶之后没有任何时间兜底：与任务无关的插件进程持续耗 CPU / I/O、反复崩溃重启的 helper（每个观察窗都有进程生灭）、某台机器的空闲基线本身高于阈值，都会无限续命。工作目录被别的写入者共用时也一样——未隔离的运行、同目录的其他 worker、Lead 自己在改文件，别人的写入会被读成本运行的工作树变化（真机验证里撞上了，见"验证"）；每个运行独占工作树的隔离派发不受影响。此时唯一的出口是 Lead 的判断（CLI `status` 的 advisory、等待类命令的活性字段）与 stop。
- **证词也可能漏掉真的在推进的运行**：宿主进程内部的工作、祖先链断了的后代、两次取样之间出生又退出的短命进程，进程项都看不到；被 `.gitignore` 排除的写入、非 git 工作目录，工作树项看不到；低 CPU 的等待型工具（`sleep`、等远端应答且无流量）两项都读不出活动。这些形态仍会在预算处被收口——按 Owner 的口径，读不出任何活动即"没有生命体征"。
- 流分片是上游内部遥测通道，形状只在 zcode CLI 0.16.9 实测过；上游改形状则识别不到，行为退回只看进度与本机读数。
- 进程活跃度阈值来自一次探针、一台机器、一组插件配置，不是长期统计。父子关系取自 `Win32_Process.ParentProcessId`，未做创建时间校验。
- 进程快照不适用（非 Windows）且工作目录不是 git 仓库时两项证词都没有，立即收口。进程快照瞬时失败（命令失败、超时、结果里找不到宿主进程）下一拍重取；连续三次失败按"取不到"处理——那是**活动状态未知**，不是证明没有生命体征，但仍会收口。
- 进程活动与工作树变化续命期间转录没有新事件：等待类命令显示 `process_only`，Lead 看到的是"最近一次动作是那条命令、已过去多久"。没有为此新增事件类型。
- advisory 陈述的是**转录可见**的事实：zcode 的正文到轮末才落转录，工具在途的输出也不进转录——"转录里没有"不等于 worker 没在产出。
- 诊断里的"零 worker 事件"事实不限于启动期：任何以非零退出码结束、退出前没有 `run.event` 的运行都会附上（很晚才静默崩溃的也算）；只有初始化遥测、没有模型工作的运行不会附（遥测也是 `run.event`）。
- stop：`hostPid` 只对本决定之后派发的运行存在，此前的 zcode 运行仍报无路由，需手动结束进程树。击杀前不校验该 pid 仍是原进程（非终态运行的进程已死且 pid 被系统复用时会误杀）；`verified` 核验的是该进程已退出，不是逐个证明它的全部后代都已消失；会话与重放事实是 runId 绑定读取，外 run 的尾行换不走目标，但能往本 run 转录里写绑定行的一方可以——以上三点与 `proc_<pid>` 路由同等，是既有信任边界。
- 有生命体征的运行会一直占着它的工作树；tokenBudget 对 zcode 兜不住（到完成阶段才上报 usage）。

## 会审（consult_202610122009151949omru6，审提交 63214ee）

两席都判 FIX_FIRST。sol：与 Owner 口径 DEVIATES、有新缺陷；kimi：口径 MATCHES、有一处新引入的误路由。

| 问题 | 提出 | 处置 |
|---|---|---|
| resume 重放换了进程，stop 仍用 `session.created` 里的旧 `hostPid`：旧进程已退出时报"已核验停止"而新 worker 还在跑，旧 pid 被复用时杀错对象 | 两席（必改） | `run.rerun` 记新 `hostPid`；stop 的目标在重放之后取重放记录（`proc_<pid>` 路由同一缺口一并修）；重放记录没带 `hostPid` 时不沿用旧值、报无路由 |
| 进程取样期间到达的流分片被旧读数盖掉：比对一返回就收口，文案还写"没有流分片" | sol（必改，内存回放复现） | 比对得出"没有活动"后不当拍收口，下一拍轮询仍无进展才执行 |
| 零 part 阶段的两道门只看流分片、不取进程证词 | sol（必改）；kimi（近不可达，建议写明） | 三道门统一走同一套取证 |
| "子进程写文件 = 已算进程活动"不成立：低速写文件 CPU / I/O 都在阈值之下 | sol | 新增工作树变化一项 |
| 成功的快照命令里找不到宿主进程、输出为空，会被当成"不适用"立即收口 | sol | 改为瞬时失败（抛错重取） |
| 同一 pid 累计读数回退被钳成零，识别不出进程已换 | sol | 按一次退出加一次新生计 |
| "没有任何自动上限"的范围、证词的假阳与假阴、stop 的 `verified` 含义、advisory 与诊断事实的适用面 | 两席 | 写入"诚实边界" |

| 诊断事实判据看的是整个作用域，不是退出之前 | sol | 改为只看退出事件之前 |
| 测试缺口：取样中来流、零 part 进程活跃、resume→stop、silentTimeout 让位、比对阶段取样失败、advisory 边界值、pid 复用 | 两席 | 均已补 |
