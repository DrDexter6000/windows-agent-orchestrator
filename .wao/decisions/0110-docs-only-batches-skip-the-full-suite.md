# 0110 只改文档的批次不跑全量

- 日期：2026-11-04
- 状态：accepted
- 来源：Owner 2026-11-04 问"增加这么一句话都要做全量测试，是行业常规操作还是我们的WAO项目中有某个要求"；看过 Lead 的审视后答"同意你的建议，把两条例外合成一条"。
- 关系：部分取代 0077：决定第 1 条（每批在最终候选上跑一次全量）不再适用于只改文档的批次，"否决的备选"里"只改文档的批次不跑全量"一条改为采纳；0077 其余不变。操作规则的归宿仍是 `docs/testing.md`。

## 背景

- 0077 否掉这条备选的理由是：维护机器上全局 `wao` 和各宿主的 MCP 都跑主检出，合入 main 的错误会立刻影响在用的会话。这条理由管的是会被执行的文件。`.md` 不被执行。运行时读文档的代码（例如 doctor 比对 `SKILL.md`、`wao worktree reclaim` 从文档和决定里找被引用的提交）在全量里用临时仓测，真实文档改动的影响全量看不到；宿主经技能链接直接加载的 `SKILL.md` 也一样。
- 文档改动能弄坏的只有读文档的测试：横切守卫组，以及按文件名能搜到、或经 `test/_usageDocs.mjs` 读这些文档的测试文件。0077 自己记的也是"全量额外抓到的问题都来自横切静态守卫"。
- 此前有两处规矩：全量之后只补改 `docs/**` 可以不重跑（`SKILL.md` 与角色合同除外）；整批只改文档仍要跑一次全量。于是给 `SKILL.md` 加一句话也要占机器十几分钟，会审改一个措辞就再跑一遍。worker 交付早已按 0077 第 3 条，只改文档的用定向验证。

## 决定

1. 要合入的改动里，没被一次全量覆盖的部分只有 `.md` 文档时，跑横切守卫组，加上读这些文档的测试（怎么列出见 `docs/testing.md`），不跑全量。整批只改文档、全量之后只补改文档，都按这一条。
2. 会被注入 worker 的 `.md`（角色合同 `config/roles/*.md`）不在此列：派发时按目录读取并注入，测试也按目录读它们，搜索列不全。`SKILL.md` 不再像此前那样排除：读它的测试按文件名都能搜到（守卫组之外如 `m12-24-providerCapacityTruth`），全量对它多不出别的检查。
3. 只改画像数据的批次仍按 0089 §6。

## 否决的备选

- **维持原状**：对纯文档改动，全量多不出信息，只多出等待。
- **连同角色合同一起放开**：理由见决定第 2 条。

## 已知边界

- 读文档的测试靠搜索列出；文件名也分段拼出、又不经 `test/_usageDocs.mjs` 读文档的测试若被文档改动弄红，要到下一次全量才发现。
