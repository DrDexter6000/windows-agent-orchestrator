## 决定

1. **范围：每个运行目录一个看板，覆盖目录里的全部项目。** 授权从"按工作区精确匹配运行 cwd"改为"运行属于这个运行目录 + 运行的项目事实"，列表、详情、事件流共用同一授权。浏览器只拿到项目 slug 与项目名。`--cwd` 只作初始项目筛选。分支工作树未带共享 `--run-dir` 时运行写进自己的运行目录，主看板看不到，这是既有规矩。
2. **常驻实例，独立启动协议。** `wao dashboard` 找已在跑的实例，否则拉起；拉起复用 `runnerLaunch.js` 的 WMI 创建层（决定 0120），不复用 runner 的一次性交接桥。实例记录（nonce、pid、启动时间、端口、build）在监听与认证握手可用后原子发布；短时启动锁、带期限的启动代际，迟到的子进程失去发布资格即退出。状态目录按用户 SID 设 ACL。浏览器 URL 只带一次性短时启动码，页面凭它换会话令牌，长期令牌不进 URL、命令行与日志。运维出口 `status` / `stop` / `restart`，build 不一致时提示 restart。不开机自启、不设闲置退出。
3. **观察边界：保留与修订。**
   - 保留：只监听 127.0.0.1；固定静态资源与不带令牌的 `/health` 之外，每个请求验 bearer；只许 GET；无 CORS；严格 CSP；no-store；固定错误；参数闭集；纯文本 DOM；没有改动类控件；动态文本先脱敏、清控制字符、限长。
   - 修订：Owner 专用有界投影显示命令与工具文本（头尾行与总行数，全文按 `runId#seq` 有界分页）、绑定任务书正文、工作树内的相对路径（工作树外路径仍为 `[path_withheld]`，自由文本里的绝对路径折成末段；隔离违规事件的脱敏路径例外）；受控产物接口只从已证明的交付提交读 Git 对象（png/jpeg/webp，限大小，禁 SVG）；页面可请求闭集内的多个只读接口。DTO 走白名单，不整包透传应用层对象。
   - 理由：Owner 要看 worker 在做什么；说不出防什么的限制只会让面板失去用途。
   - 已知不防（第 141 批会审后 Lead 定）：本机有人在两次检查之间换联接或建硬链接；图片只验首个结构段（固定图片 MIME 加 `nosniff`，只经 `<img>` 显示，没有执行脚本的路径）；图片对象单独缺失时详情仍标 `bound`，产物接口如实返回 404。
   - 第 141c 批：Activity 接口按真实 seq 翻页（缺口、冲突、无号如实标出），全文按 `runId#seq` 分页并按转录 hash 缓存，超长单条只处理头尾窗口。已知不防：不带盘符的 `\Users\…`、紧贴 URL 或收尾引号的路径、名单外的根（如 `/srv`）折叠不准；超过 8 KiB 的秘密跨窗口截点时列表摘录可能露出片段（全文完整脱敏）；超长无号区间翻页可能不全（真实转录全部带 seq）。
   - 第 142 批：`/v2` 新前端（顶部条、三页导航、中英文、Overview、Attention），与旧界面并存；固定静态资源表扩为多文件闭集，含 `.`、`..` 段或重复斜杠的请求一律 404。本条授权守卫迁移："只许两个接口、只许一处 fetch"改为只约束旧界面，`/v2` 另立同等守卫（接口闭集、一处 fetch、不用 innerHTML 一类写法、无动效）。事项证据带真实事件号；额度用尽同时计入 Alerts（Owner 已定第 3 条）。已知局限：车道重置时间暂无数据，显示最近观测；同一故障的连续重试尚未合并成一行。
   - 第 143a 批：Workers 页与侧栏。授权守卫迁移："页面不许读 `.prompt`"只约束旧界面；`/v2` 接口闭集加 `/api/worker`、`/api/artifact`；只有 `/v2` 静态资源的 CSP 加 `img-src blob:`。列表行加当前提交、文件数与本席结论，不带路径。
4. **实时事件：带令牌的 `fetch` 读 SSE，退回 5 秒轮询。** 事件 seq 与传输游标分开；同一 seq 的就地更新作为 update 补推；游标带流代际，失效时服务端回 reset；终态排空并对账后关闭流。
5. **标题与类型。** 标题取绑定任务书的第一个非空行（跳过代码围栏与分隔线；是 Markdown 标题时去掉 # 记号），脱敏限长，缺失显示 run 号。全文第一个标题常是正文中段的小节名（真实转录 3,041 个运行里 467 个两种取法不同），所以不用。类型的权威顺序：会审事实 > 显式标签 > 绑定角色推导；推不出为 `Untyped`。类型在派发事实中固化，并在续修、retry、会审席传播；CLI retry 补持久的 `retryOf`。MCP `run_dispatch` 只加可选 `taskType:"image"`，按 Owner 批准为它抬工具面字节帽（只抬所需的量，0021 追加记录）。
6. **启动阶段如实显示。** 用绑定的 `projectExecutionStage` 把未进入 active 的运行显示为 `Starting`，无阶段依据时显示"阶段未知"；不虚构队列。
7. **读模型只在内存。** 服务进程内一次冷普查加按文件身份增量刷新；缓存事实，时效类判定在发布快照时按同一个 `now` 现算；不建持久索引。

## 不采纳

- **浏览器原生 `EventSource`**：不能带 `Authorization` 头；把令牌挪进 query 或 Cookie 会扩大暴露面。
- **一台机器一个看板**：运行事实按运行目录存放，多个运行目录本就各自独立；跨目录发现没有可证明的边界。
- **持久化的看板索引**：架构约定不建第二个持久索引；冷普查加增量足够，且无需迁移与一致性维护。
- **"言行不符"用正则识别 worker 自述**：误报不可控；Owner 定本期不交付，待结构化自述另立台账。
- **`taskType` 六值让 Lead 手填**：五类可从会审与角色推出，手填会造成与角色冲突的类型；只给推不出的生图开口。
- **旧测试按文件整删**：其中的令牌、乱序、A→B→A、失败保留上次数据、终态退出码修复等通用防线须先迁到新入口。
