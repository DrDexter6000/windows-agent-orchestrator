## §1 双层机制

**L1 确定性控制面门（真牙齿）**——判定 SSOT=`src/application/nestedDispatchGuard.js`（纯函数，env/cwd 注入）：
- 检测 a：环境标记 `WAO_IN_WORKER=1`（WAO 派生的 backend 子进程 env 注入——processBackend/deepSeekAcp spawn env；worker 的 shell/子进程/其会话拉起的 MCP 服务实例全链继承）。
- 检测 b：cwd 落在 `.wao-worktrees/` 内（覆盖 HTTP-attach 型 backend：kimi-web 工具执行在 serve 侧、env 标记不可达，但工作目录绑定在本 run 的 worktree）。
- 豁免：`WAO_ALLOW_NESTED_DISPATCH=1`（Lead 显式，如 worktree 内合法测试场景）。
- 消费点三处（同一函数零分叉）：RunManager.start（一切派发单一咽喉：CLI run/spawn、MCP run_dispatch、consult 扇出、resume）；MCP run_dispatch/run_consult/run_continue 处理器头（worker 会话拉起的 MCP 服务实例在 side effect 之前被拒）。
- 拒绝文案固定（typed `nested dispatch refused (decision 0047)`），不回显调用方可控内容。

**L2 合同提示（软层）**——角色合同合成面统一附加 WQ-03 NO-NESTED-DISPATCH 条款（`src/application/roleContract.js` WORKER_EVIDENCE_DISCIPLINE 第三条）：告知模型禁令（不含 wao CLI/WAO MCP 工具/wao-orchestrator skill）；L1 保证即使模型尝试也确定性失败。条款在合成面而非角色文件——rolePin（文件 sha）不动，无 drain-window 影响；对全部带角色合同的派发生效（显式+legacy 头路径）。
