## Context

0034 立法了状态卫生原则但以散文形态存在；清洁后的结构没有机制守护。双席咨询收敛出三层防线（环境力学/控制面/守卫）与六条 LLM 行为规律（决策点局部性、造物偏好逆用、可逆性当场证明、会话失忆、省事路径必胜、规则自身也被囤积）。Owner 于 2026-09-30 批准整体方案。

## Decision

1. **修订 0034 §5**：反税条款继续有效，但**允许本决定登记的守卫库存**（≤8 项，每项一行登记：检查的不变量/修复命令/立法日期）。库存外的任何新守卫/工具/定时任务仍禁止、仍需 Owner 具名批准。
2. **守卫库存（首批 5 项，载体 `scripts/hygiene.mjs` + `npm run hygiene`）**：
   - W1 `.wao/runs` 根白名单（逐条带理由；增删=改清单+declare）；
   - W2 墓碑双向完整性（[墓碑]→归档件存在；归档件←有墓碑指回）；
   - W3 续接入口（`.strategy/AGENTS.md` 必须处于"已关闭"或指向恰好一个非墓碑活页）；
   - W4 `wao/run_*` 分支棘轮帽 175（现值 151+余量；调高=改本文件+declare）；
   - W5 worktree 注册漂移（注册路径消失或落在未登记根集合之外=红；外部根 allowlist 逐条带理由）。
   每条红线的失败输出必须自带修复命令（绿灯公理）。
3. **落位纪律**：文件系统状态（B 类）只进 `npm run hygiene`（R23-D §7：worktree 内看不见主仓 gitignored 状态，不进交付验证波）；git 管理性状态（A 类）后续阶段进 npm test（先在 hygiene 证明稳定）。
4. **闭合挂钩**：milestone-discipline §8 增补——工作流/阶段闭合时跑 `npm run hygiene` 并把结果贴进闭合记录。
5. **已批准的后续阶段**（各自走正常验收路径，不因本决定豁免）：S2 A 类守卫进 npm test；S3 派发时 advisory 资源计数行（fail-open，沿 machineGatePaths 先例）；S4 工作流脚手架合同（日期目录+预置墓碑位+首行标记，闭合=零决策默认）；S5 `runs delivery closeout` 独立命令（幂等闸门序列：已决终态→非脏→活文档引用零命中→bundle 当场哈希→worktree remove→分支删除；`--force-with-reason` 走 declare；≥10 次真实闭合后再议 decide 耦合——decide 契约禁止删除，耦合需二次裁定）。
6. **明确不做**：pre-commit hook（不可见即会无声死亡）、cron/守护进程（janitor 寄生既有调用）、新 SOP/平台/更多散文。

## Consequences

- `npm run hygiene` 红=阻断闭合的正当理由；修复或（具名+declare）调整清单后复绿。
- 白名单/阈值/allowlist 的每次调整=git 留痕+declare 披露；Lead 不得为变绿自行扩列（auditor 四层元规则）。
- 本库存登记即"守卫的守卫"第一层：8 槽位占用 5，剩余 3 槽预留给 S2/S5 及一个真实痛点名额。
- 诚实上限不变：机制让偏离可见、恢复便宜，不承诺让偏离不可能。
